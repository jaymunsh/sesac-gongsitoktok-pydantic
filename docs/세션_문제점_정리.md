## A. 핵심 버그 (해결)

### A-1. 기간 질문이 corpus 근거 0건 → 빈 거절 ✅
- **증상**: "2024/2025년 사업보고서 기준 보통주 발행 주식총수는?" → "자료가 제공되지 않아 확인 불가" (과거 CrewAI는 정상 응답).
- **원인**: 기간 필터를 **문자열** `rcept_dt`에 Chroma 숫자 연산자 `$gte/$lte`로 걸어 벡터 쿼리가 `ValueError`. 그 예외가 `asyncio.gather(return_exceptions=True)`에 **로그 없이 삼켜져** corpus가 `[]`.
- **심각도**: 높음 — 기간 표현이 들어간 **모든 질문**이 영향.
- **조치/위치**: 필터 기준을 사업연도(`bsns_year` int)로 전환. `app/services/chat.py`(`_date_where`), `app/rag/vectorstore.py`. 검증: `ss-ret-fy-*`, `ss-period-shares`.

### A-2. "2024년 사업보고서"가 FY2023 보고서를 가리킴 ✅
- **증상**: 연도 지정 답이 한 해 어긋남(접수연도 기준).
- **원인**: 기간을 **접수일(rcept_dt)**로 해석 — 사업보고서는 FY+1에 제출되므로 접수연도 ≠ 사업연도.
- **심각도**: 중 — 의미 오답 가능.
- **조치/위치**: `report_nm`("…(2024.12)")에서 **사업연도 파싱**해 `bsns_year`로 필터 → "2024년"=FY2024. `vectorstore._bsns_year`.

### A-3. 재무·요약 트랙이 기간을 무시 (트랙 불일치) ✅
- **증상**: corpus만 기간을 거르고 재무/요약은 안 걸러 **한 답 안에서 연도 엇갈림** 가능.
- **원인**: 재무(`fetch_financial_citations`)는 항상 최신연도, 요약(`search_summaries`)은 `where` 미수신.
- **심각도**: 중.
- **조치/위치**: 재무에 요청 사업연도 전달(미존재 시 최신 폴백) `app/services/financials.py`; 요약에 `where` 전달 `vectorstore.search_summaries`. 검증: `ss-fy-financial`, `ss-fy-summary`.

## B. 같은 결의 잠복 위험 (감사로 발견 → 해결)

### B-1. 조용히 삼키는 예외 (가시성 0) ✅
- **증상/위험**: `gather(return_exceptions=True)`가 corpus·재무·거시 실패를 **로그 없이** `[]`로 처리 → A-1 버그를 가린 바로 그 메커니즘. 다른 원인의 실패도 똑같이 숨음.
- **조치/위치**: `_ok()`로 언랩 — graceful은 유지하되 **반드시 `log.warning` 로깅**. `app/services/chat.py`.

### B-2. 인제스트 실패가 조용히 누락 ✅
- **증상/위험**: 적재 중 일부 공시 실패가 print만 되고 묻힘.
- **조치/위치**: 적재 종료 시 `⚠️ N건 실패` 요약 경고. `app/ingest/pipeline.py`.

### B-3. 저장 타입 ↔ 쿼리 타입 불일치 (rcept_dt 문자열) ✅
- **원인**: 범위 비교가 필요한 날짜를 문자열로 저장(= A-1의 직접 원인).
- **조치/위치**: `rcept_dt`도 int 저장·읽을 때 str 복원, `_match_where` int 우선 비교. 마이그레이션 `scripts/migrate_rcept_dt_int.py`.

## C. eval 공백 (메타 문제) ✅
- **증상**: 골든·행동·검색 어디에도 **기간 한정 질문 케이스가 없어** A-1이 오래 방치됨.
- **조치/위치**: `eval_retrieval`에 사업연도 필터(`fy_from/fy_to`) 지원 추가 + 결정적 가드 `ss-ret-fy-*`, E2E `ss-period-shares`·`ss-fy-financial`·`ss-fy-summary`. (검색 13/13·MRR 0.933, 골든 15/15, 행동 6/6 — 회귀 0)

## E. 프로세스/판단 메모 📌
- **B와 C(의미)가 엮여 있었음** — 재무·요약에 단순히 날짜를 흘리면 corpus(접수일)와 새 불일치가 생겨, "흩어 고치기" 대신 **사업연도 단일 모델**로 통합한 게 핵심 판단.
- **재적재 금지 제약 준수** — 모든 변경을 **메타 백필**(재임베딩·DART 호출 없음)로 처리.
- **검증을 무료·결정적 계층(검색 eval)에 박제** — LLM 변동과 무관하게 재발 방지.

## 교훈 5줄
1. 삼키는 graceful은 반드시 **로깅**을 동반(안 그러면 버그를 가린다).
2. 범위 비교가 필요하면 **숫자로 저장**(Chroma `$gte/$lte`는 숫자 전용).
3. **도메인 시간축 구분** — 사업연도 ≠ 접수일.
4. **병렬 트랙은 같은 필터 공유** — 안 그러면 한 답에서 값이 엇갈린다.
5. **eval 공백 = 방치된 버그** — 발견 즉시 결정적 가드로 박제.
