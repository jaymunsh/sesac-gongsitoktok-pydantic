# 인제스트 설계 확정 — 삼성 사업보고서 1건 샘플 검증 결과

> 보고서 §6-1 "1) 청크/Contextual 설계 + 1건 샘플 검증 → 메타 스키마·컬렉션명·문맥 형식 확정"의 산출물.
> 검증 대상: 삼성전자 사업보고서 `20250311001085` (제56기, 2024.12) · 원문 6.9M자.
> 작성일: 2026-06-22 · 비용: 파싱/청킹 $0, 검색 스모크 ~$0.01 (전체 재적재 아님)

---

## 0. 결론 (확정)
표-인식 파싱 → 표-인식 청킹 → Contextual 문맥 주입 → 메타 태깅까지 **1건으로 검증 완료**.
아래 스키마·컬렉션명·문맥형식을 **확정**하고, 사용자 확인 후 전체 33건 재적재로 진행한다.

## 1. 컬렉션명 (확정)
- **코퍼스(원문 청크): `corpus_<corp_code>`** — 회사 1곳 = 1 컬렉션. 공시 여러 건을 한 컬렉션에 넣고 `rcept_no`/`rcept_dt` 메타로 필터.
  - 삼성 `corpus_00126380` · 현대 `corpus_00164742`
- 사전요약: `summary_<corp_code>` (별도 저장소, 본 단계 범위 밖)

## 2. 메타데이터 스키마 (확정) — `app/schemas/ingest.py::ChunkMeta`
| 필드 | 예 | 용도 |
|---|---|---|
| `corp_code` / `corp_name` | `00126380` / `삼성전자` | 컬렉션·출처 |
| `rcept_no` | `20250311001085` | 공시 식별·중복적재 방지·출처추적 |
| `report_nm` | `사업보고서 (2024.12)` | 출처 표시 |
| `rcept_dt` | `20250311` | **날짜 메타필터 키**(기간 질의) |
| `pblntf_ty` | `A` | 공시유형(A=정기 등) |
| `section_title` | `II. 사업의 내용 > 1. 사업의 개요` | 섹션 경로(`>` 구분), 출처·필터 |
| `kind` | `text` / `table` | 본문/표 구분(인용 표시·랭킹) |
| `order` | `25` | 문서 내 순서 |

- 청크는 `text`(=문맥줄+원문, 임베딩/BM25 대상)와 `raw_text`(인용·표시용 원문)를 **분리 보관**. `chunk_id = <rcept_no>-<order 4자리>`.

## 3. Contextual 문맥 형식 (확정) — 결정적(무료) 1줄
```
[<회사> · <공시명> · <섹션경로> · (표면 표제목) · <종류>]
<원문 또는 Markdown 표>
```
실제 예(연결 손익계산서 청크):
```
[삼성전자 · 사업보고서(2024.12) · (첨부)연결재무제표 · 연결손익계산서 · 표]
| 과목 | 주석 | 제 56 (당) 기 |  | 제 55 (전) 기 |  |
| Ⅰ. 매출액 | 29 |  | 300,870,903 |  | 258,935,494 |
| Ⅳ. 영업이익 | 29 |  | 32,725,961 |  | 6,566,976 |
```
- **결정적 문맥**(메타→템플릿)을 기본 적용: LLM 비용 0. 보고서의 "기업·기간·공시명·섹션 한 줄"을 그대로 충족.
- **LLM Contextual(Anthropic식 1문장 상황설명)은 선택적 보강**(gpt-4o-mini, 청크당 1콜 ~$3). 풀 빌드 전 적용 범위를 사용자와 확정(비용 변수). 훅: `app/ingest/contextual.py`.

## 4. 표-인식 파싱 (확정) — `app/ingest/parser.py`
- DART `document.xml`(ZIP→raw XML, 태그 보존)을 BeautifulSoup(lxml)로 순회.
- `<TABLE>`→**Markdown 표**(행·열·`COLSPAN` 패딩 보존), `<P>`→본문, `<TITLE>/<SECTION-*>`→섹션 경로.
- 표 셀 4종(`TD/TH/TE/TU`) 모두 셀로 취급. 자간 라벨("매 출 액"·"주 석") **경계검사 정규화**로 붙임(BM25 매칭↑, 오병합 0).

## 5. 청킹 규칙 (확정) — `app/ingest/chunker.py`
- 본문: 섹션 유지 + 슬라이딩 윈도우(`chunk_size=800`, `overlap=120`).
- 표: 통째 1청크. 크면(`table_max_chars=2400`) **헤더 반복하며 행 단위 분할**. 단 헤더가 비정상(거대 셀)이면 반복 금지 + 긴 행 하드 분할(청크 폭증 방지 — 초기 버그 수정 완료).

## 6. 하이브리드 검색 (초기 구현 + 발견사항) — `app/rag/vectorstore.py`
- 벡터(text-embedding-3-small) 후보 + BM25(콤마 숫자 토큰 보존) 가중합(`bm25_weight=0.4`).
- **검증**: "영업이익"→연결손익계산서 표 적중 ✓, "사업 내용/반도체 메모리"→정확 섹션 ✓.
- ⚠️ **발견**: "연간 매출액 얼마야" → 손익계산서 청크가 벡터 top-30 밖·BM25 26위로 누락. "매출액"이 든 청크가 수십 개라 **정확 재무 라인아이템은 RAG 단독으로 약함**.
  - → 아키텍처가 이미 대응: **정확 재무수치는 `재무 결합` 노드(DART 정형 `fnlttSinglAcnt`)가 1급**, RAG는 백업(보고서 §4-2). 골든셋 매출/영업이익 exact 값은 정형 재무 경로로 충족.
  - → 런타임/RAG 단계 개선안: ① 전체 코퍼스 BM25 union(현재는 벡터 후보 내 재랭킹) ② 재무질의 시 `재무제표`·`표` 가점 도메인 리랭커 ③ `candidate_k`↑. **인제스트 설계 변경 불필요.**
