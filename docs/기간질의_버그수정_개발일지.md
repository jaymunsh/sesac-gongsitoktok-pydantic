# 기간 질의 버그 수정 — 개발 일지 (2026-06-23)

> **한 줄 요약**: "2024년 사업보고서 기준 …" 같은 **기간 한정 질문이 빈 거절로 응답되던 버그**를 발견·수정했다.
> 근본 원인은 ①날짜필터가 Chroma 타입을 위반해 **조용히 0건**이 된 것, ②기간을 **접수일**로 해석한 의미 어긋남,
> ③corpus만 기간을 거르고 **재무·요약 트랙은 무시**한 불일치. 세 가지를 **사업연도(`bsns_year`) 기반 단일 모델**로 통합 해결했다.
>
> 대상 레포 `gongsitoktok-pydantic` · 종합 설명서(`docs/AI_프로젝트_종합설명.md` §12-5)와 연동.
> 본 문서는 종합 설명서에 이미 정리된 작업과 **별개로**, 이번에 발견된 오류의 발견→진단→수정→검증 과정을 단독으로 남긴 기록이다.

---

## 1. 발견 경위 (증상)

같은 두 질문을 **과거 CrewAI+RAG 버전**과 **현재 PydanticAI 버전**에 던졌을 때 결과가 갈렸다.

| 질문 | 과거(CrewAI+RAG) | 현재(PydanticAI, 수정 전) |
|---|---|---|
| "2025년 사업보고서 기준 보통주 발행 주식총수는?" | ✅ 5,969,782,550주 | ❌ "2025 사업보고서 자료가 제공되지 않아 확인할 수 없습니다" |
| "2024년 사업보고서 기준 보통주 발행 주식총수는?" | ✅ 5,969,782,550주 | ❌ "제공된 근거에는 자산총계·부채총계·자본총계·매출액·영업이익·당기순이익만 있을 뿐 …" |

- 두 번째 답의 *"자산총계·부채총계·자본총계·매출액·영업이익·당기순이익만 있을 뿐"* 문구가 단서였다.
  이 6개는 정확히 **DART 정형재무 API(`fnlttSinglAcnt` 주요계정)**가 주는 항목 = `financials._KEY_ACCOUNTS`.
  → writer가 받은 [근거]에 **corpus 청크가 없었다**(재무 6개만 있었거나, 비어 있었다)는 신호.

## 2. 진단 (재현 → 격리)

LLM 없이 검색만 떼서(무료·결정적) 단계적으로 좁혔다.

1. **데이터 존재 확인** — `corpus_00126380`에 "I. 회사의 개요 > 4. 주식의 총수 등" 청크 292개, 최신 사업보고서(2024.12)에 `5,969,782,550` 포함. → **적재는 정상.**
2. **검색 단독 확인** — 쿼리 "보통주 발행 주식총수"는 "발행"에 끌려 "증권의 발행을 통한 자금조달 실적" 표를 상위로 올리는 등 랭킹 민감성은 있었으나, 근거 자체는 회수 가능.
3. **`_retrieve` 전체 재현 — 0건** — 라우터+검색+재무를 실제 경로로 돌리니 **citations 0개**. 여기서 결정적 단서 확보.
4. **예외 격리** — `store.search`에 날짜 `where`를 직접 넣어 보니:

```
필터 없음            → 5개 정상
{rcept_dt:{$gte:'20240101', $lte:'20241231'}}  → ValueError:
   Expected operand value to be an int or a float for operator $gte, got 20240101
{rcept_dt:'20240312'} (문자열 eq)               → 정상  ⇒ rcept_dt는 '문자열'로 저장돼 있었다
```

→ **Chroma는 `$gte/$lte` 피연산자를 숫자로만 받는데 `rcept_dt`는 문자열**. 벡터 쿼리가 `ValueError`를 던졌고,
그게 `asyncio.gather(return_exceptions=True)`에 **조용히 삼켜져** corpus가 `[]`가 됐다(`chat.py`).
→ **기간 표현이 들어간 모든 질문**이 corpus 근거 0건이 되는 광범위 버그였다.

## 3. 근본 원인 (3겹)

| # | 원인 | 성격 |
|---|---|---|
| ① **크래시(조용한 0건)** | 문자열 `rcept_dt`에 Chroma 숫자 연산자 `$gte/$lte` → `ValueError` → `return_exceptions=True`가 **로그 없이 삼킴** | 타입 불일치 + 삼킨 예외 |
| ② **의미 어긋남** | 기간을 **접수일(rcept_dt)**로 해석. 사업보고서는 FY+1에 제출되므로 "2024년 사업보고서"(통념=FY2024)가 사실상 FY2023 보고서를 가리킴 | 도메인 시간축 혼동 |
| ③ **트랙 불일치** | 재무(`fetch_financial_citations`)는 항상 최신연도, 요약(`search_summaries`)은 `where` 미수신 → corpus만 기간을 거르고 두 트랙은 무시 → 한 답 안에서 연도 엇갈림 | 병렬 트랙 필터 미공유 |

> **왜 eval이 못 잡았나**: 골든/행동/검색 케이스에 **기간 한정 질문이 하나도 없어** 이 코드패스가 미커버였다.

## 4. 수정 — 사업연도(`bsns_year`) 단일 모델로 통합

세 원인이 엮여 있어, 흩어 고치는 대신 **기간 필터 기준을 접수일→사업연도로 통일**했다.
`report_nm`("사업보고서 (2024.12)")에 사업연도가 이미 있어 **재임베딩·DART 호출 없이 메타만 백필** 가능.

| 영역 | 변경 | 파일 |
|---|---|---|
| **필터 기준 전환** | `bsns_year`(int) 메타 추가·필터. `_date_where`가 사업연도 `$gte/$lte`(int) 생성 | `rag/vectorstore.py`, `services/chat.py` |
| **A: 예외 가시화** | gather 결과를 `_ok()`로 언랩 — 예외는 graceful `[]`로 두되 **반드시 로깅**(`log.warning`) | `services/chat.py` |
| **B-재무** | `fetch_financial_citations(corp_code, year)` — 요청 사업연도 조회, 미존재 시 최신 폴백 | `services/financials.py` |
| **B-요약** | `search_summaries(..., where)` — corpus와 동일 사업연도 필터 적용 | `rag/vectorstore.py`, `services/chat.py` |
| **C: 의미 정합** | "2024년"=FY2024로 매핑(접수일 아님). 세 트랙 동일 사업연도 | (위 전환에 포함) |
| **D: 적재 가시성** | 인제스트 실패를 끝에 `⚠️ N건 실패`로 한 번 더 경고 | `ingest/pipeline.py` |
| **타입 정합** | `rcept_dt`도 int 저장(읽을 때 str 복원), `_match_where` int 우선 비교 | `rag/vectorstore.py` |

**마이그레이션(일회성, 재임베딩 없음)**
- `scripts/migrate_rcept_dt_int.py` — `rcept_dt` 문자열 → int (68,211건)
- `scripts/migrate_bsns_year.py` — `report_nm` 파싱 → `bsns_year` int 백필 (68,211건, 미상 0건)

> ⚙️ **운영 주의**: 마이그레이션을 떠 있던 서버 중에 했다면, BM25 인메모리 인덱스가 옛 메타를 캐시 중이므로
> **uvicorn 1회 재시작**으로 반영(껐다 켜기). 새 프로세스/eval은 자동 반영.

## 6. 추가 점검에서 정리한 잔존 사항

| # | 사항 | 조치 |
|---|---|---|
| 1 | 마이그레이션 후 BM25 캐시 — 떠 있던 서버는 재시작 필요 | **배포 시 1회 재시작** |
| 2 | `bsns_year=0`(미상) 미세 누수 — `$lte`-only 필터에 섞일 여지 | 현재 미상 0건이라 무해(추적만) |
| 3 | 연도 정밀도는 라우터의 `date_from/to` 채움에 의존(LLM) | 못 채우면 무필터로 graceful 저하, E2E 케이스로 커버 |
| 4 | 미래연도 질문(미제출) → 재무 최신연도 폴백 라벨 불일치 | graceful, 답은 근거 기반 |

## 7. 교훈

1. **삼키는 graceful이 진짜 버그를 가린다** — `return_exceptions=True`/광범위 `except`는 반드시 **로깅**을 동반.
2. **저장 타입 = 쿼리 타입** — 범위 비교가 필요하면 숫자로 저장(Chroma `$gte/$lte`는 숫자 전용).
3. **도메인 시간축을 구분** — 사업연도(bsns_year) ≠ 접수일(rcept_dt). 사용자 언어("2024년 사업보고서")의 통념을 따른다.
4. **병렬 트랙은 같은 필터를 공유** — corpus/재무/요약이 제각각 기간을 다루면 한 답에서 연도가 엇갈린다.
5. **eval 공백 = 방치된 버그** — 기간 질문 케이스가 없어 오래 숨었다. 발견 즉시 결정적 가드로 박제.
